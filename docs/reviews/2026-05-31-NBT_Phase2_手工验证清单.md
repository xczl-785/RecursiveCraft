# RecursiveCraft NBT Phase 2 手工验证清单

> 目标分支：`1.20.1`
> 适用阶段：`Phase 2` 第一阶段单来源玩家背包路径
> 文档日期：2026-05-31
> 文档定位：用于对第一阶段运行时 NBT 方案做固定手工复验，不用于多来源存储或目标产物 NBT 主动指定场景

---

## 一、适用范围

本清单只覆盖：

1. 玩家背包作为唯一真实库存来源
2. 输入材料需要区分 NBT 的运行时匹配与扣减
3. `CraftingPlanner` 仍保持 `Item` 级粗规划

本清单不覆盖：

1. 目标产物 NBT 主动指定
2. 原版相邻容器
3. 第三方存储网络
4. planner 的 NBT 节点图扩展

---

## 二、复验前置

执行复验前应确认：

1. 当前分支为 `1.20.1`
2. 服务端与客户端资源已刷新
3. 使用的样例物品能够稳定复现“同一 `Item` 不同 NBT”场景
4. 清空无关背包噪声，避免结果被外部因素干扰

---

## 三、固定复验场景

### 3.1 纯 `Item` 场景回归

目标：

- 确认旧的纯 `Item` 递归合成路径未退化

检查点：

1. 使用不含 NBT 差异的基础原版物品发起递归合成
2. 合成应成功
3. 消耗与产出数量应符合既有行为

### 3.2 同一 `Item` 不同 NBT 的正确命中

目标：

- 确认运行时会命中正确身份的输入材料

检查点：

1. 背包同时放入同一 `Item` 的多个不同 NBT 变体
2. 发起只应接受其中一种变体的递归合成
3. 成功后只应扣减匹配身份的变体
4. 其他变体不得被误扣

### 3.3 错误变体不得误用

目标：

- 确认“有同类物品但身份不匹配”不会被误判为可用

检查点：

1. 背包中只放错误 NBT 变体
2. 发起需要正确变体的递归合成
3. 请求不得成功
4. 不得发生任何部分扣减

### 3.4 recipe 候选回退

目标：

- 确认运行时 candidate 失败后能回退到其他合法 recipe

检查点：

1. 构造一个目标物品，其候选 recipe 至少包含两条路径
2. 让理论优先路径在运行时因为 NBT 材料不满足而失败
3. 若存在次优但合法路径，请求仍应成功
4. 若所有路径都失败，不得出现半扣减脏状态

### 3.5 revalidate 失败无部分扣减

目标：

- 确认正式提交前库存变化会导致整笔失败，而不是部分扣减

检查点：

1. 先生成可执行请求
2. 在正式提交前改变相关槽位内容或数量
3. 请求应失败
4. 不得出现部分扣减

### 3.6 输出 fallback

目标：

- 确认输出插入失败时沿用既定降级语义

检查点：

1. 构造背包空间不足场景
2. 发起成功可执行请求
3. 输入应正常扣减
4. 多余输出应掉落到世界，而不是吞掉或回滚输入

### 3.7 缺料与不支持的可观察区分

目标：

- 确认用户可观察结果能够区分普通缺料与当前版本不支持的材料语义

检查点：

1. 构造普通缺料场景
2. 构造当前 normalizer 或 matcher 无法稳定处理的场景
3. 两类结果在用户侧应可区分

---

## 四、记录格式

每次手工复验建议记录：

1. 日期
2. 构建提交号
3. 使用的样例物品或模组
4. 场景编号
5. 预期结果
6. 实际结果
7. 是否通过
8. 异常说明
