# 1.21.1 NeoForge Port Spike

Status: build spike completed. The 1.21.1 trial worktree now compiles, tests common code, and builds Fabric plus NeoForge artifacts.

## Scope

- Minecraft: 1.21.1
- Java: 21
- Platforms: Fabric and NeoForge
- Forge is intentionally replaced by NeoForge for this higher-version line.
- Seed behavior is out of scope for the mod. World-generation differences may affect a player's preferred seeds, but RecursiveCraft does not participate in village or terrain generation.

## Version Matrix

The trial uses current 1.21.1-compatible artifacts from the relevant Maven metadata:

| Area | Trial value |
| --- | --- |
| Gradle wrapper | 8.8 |
| Java toolchain | 21 |
| Architectury plugin | 3.4.164 |
| Architectury Loom | 1.7.435 |
| Architectury API | 13.0.8 |
| Fabric API | 0.116.12+1.21.1 |
| NeoForge | 21.1.233 |
| JEI | 19.27.0.340 |

Newer Architectury plugin/Loom combinations were checked first, but the tested newer Loom path failed during Gradle configuration with `ProjectDependency.getPath()` linkage errors. The spike therefore pins the older known-compatible Architectury plugin line and Loom 1.7.

## Validation Command

The initial discovery command reached the source-compile layer:

```bash
JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home ./gradlew --no-daemon --console=plain --configure-on-demand :common:compileJava --stacktrace
```

Initial result: failed in `:common:compileJava` with Minecraft/JEI API migration errors.

Current validation:

```bash
JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home ./gradlew --no-daemon --console=plain --configure-on-demand :common:test
JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home ./gradlew --no-daemon --console=plain --configure-on-demand :fabric:compileJava :neoforge:compileJava
JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home ./gradlew --no-daemon --console=plain --configure-on-demand build
```

Current result: all three commands pass.

Use `--configure-on-demand` for this branch. Without it, some Loom/NeoForge dependency source remapping paths are slower and make early feedback worse.

## Issue Categories

### 1. ResourceLocation construction

`new ResourceLocation(namespace, path)` is no longer publicly usable.

Representative files:

- `common/src/main/java/xczl/recursivecraft/RecursiveCraft.java`
- `common/src/main/java/xczl/recursivecraft/compat/jei/RecursiveCraftJeiPlugin.java`
- `common/src/main/java/xczl/recursivecraft/networking/PacketHandler.java`
- `common/src/main/java/xczl/recursivecraft/client/RecursiveCrafterScreen.java`

Resolution: centralized ID creation behind `RecursiveCraft.id(...)`, which now uses the 1.21 factory API.

### 2. ItemStack NBT to data components

The current code still relies on `ItemStack#getTag`, `setTag`, `getOrCreateTag`, and `ItemStack.isSameItemSameTags`.

Representative files:

- `common/src/main/java/xczl/recursivecraft/client/CraftableItemList.java`
- `common/src/main/java/xczl/recursivecraft/client/CraftableTarget.java`
- `common/src/main/java/xczl/recursivecraft/compat/jei/RecursiveCraftJeiRuntime.java`
- `common/src/main/java/xczl/recursivecraft/compat/jei/RecursiveCraftTransferHandler.java`
- `common/src/main/java/xczl/recursivecraft/recipe/DebugTaggedResultRecipeSerializer.java`
- `common/src/main/java/xczl/recursivecraft/runtime/material/DefaultMaterialIdentityNormalizer.java`
- `common/src/main/java/xczl/recursivecraft/runtime/material/TargetOutputSpec.java`

Resolution: introduced component-aware item identity support. `CUSTOM_DATA` is still expanded into canonical `nbt:*` fields so old material-identity behavior is preserved, while other data components remain represented as component fields.

### 3. Network buffer serialization

The packet code still uses removed `FriendlyByteBuf` helpers such as `writeId`, `readById`, `writeItem`, and `readItem`.

Representative file:

- `common/src/main/java/xczl/recursivecraft/networking/C2SExecuteCraftPacket.java`

Resolution: packet encoding now uses 1.21 registry-aware buffer and `ItemStack.STREAM_CODEC` for component-bearing stacks.

### 4. Recipe manager and RecipeHolder changes

Recipe APIs now return or require `RecipeHolder` in places where the 1.20.1 code expects raw `CraftingRecipe`.

Representative files:

- `common/src/main/java/xczl/recursivecraft/core/CraftingPlanner.java`
- `common/src/main/java/xczl/recursivecraft/core/CraftingTaskExecutor.java`
- `common/src/main/java/xczl/recursivecraft/core/TransactionCalculator.java`
- `common/src/main/java/xczl/recursivecraft/compat/jei/RecursiveCraftTransferHandler.java`

Resolution: planner/execution internals now carry `RecipeHolder<CraftingRecipe>` where recipe identity matters, while compatibility accessors unwrap at boundaries.

### 5. Custom recipe serializer rewrite

`RecipeSerializer` no longer matches the old `fromJson/fromNetwork/toNetwork` shape. The debug tagged result serializer also depends on removed ingredient/item JSON and network helper methods.

Representative files:

- `common/src/main/java/xczl/recursivecraft/recipe/DebugTaggedResultRecipeSerializer.java`
- `common/src/main/java/xczl/recursivecraft/recipe/DebugTaggedResultRecipe.java`

Resolution: debug tagged recipes were removed from the formal serializer path and downgraded to ordinary shapeless debug fixtures. This matches the product decision that the debug serializer does not need to survive the 1.21.1 line.

### 6. JEI transfer API shape

The current JEI transfer handler expects `RecipeType<CraftingRecipe>` and raw `CraftingRecipe`, but JEI 19 exposes the crafting recipe type around `RecipeHolder<CraftingRecipe>`.

Representative files:

- `common/src/main/java/xczl/recursivecraft/compat/jei/RecursiveCraftJeiPlugin.java`
- `common/src/main/java/xczl/recursivecraft/compat/jei/RecursiveCraftTransferHandler.java`
- `common/src/main/java/xczl/recursivecraft/compat/jei/RecursiveCraftJeiRuntime.java`

Resolution: JEI 19 integration now uses `RecipeHolder<CraftingRecipe>`, `RecipeHolder.id()`, and component-aware target output specs.

### 7. Smaller Minecraft API changes

Additional compile errors indicate localized API changes:

- `BlockBehaviour.Properties.copy(...)` replacement in `ModBlocks`
- `AbstractContainerScreen.renderBackground(...)` signature in `RecursiveCrafterScreen`
- `RecursiveCrafterBlock` override mismatch
- `ShapelessRecipe` constructor signature in `DebugTaggedResultRecipe`

Resolution: localized API changes were fixed during the spike.

### 8. Platform and release surface cleanup

The worktree has been renamed from Forge to NeoForge. Release/documentation cleanup completed during pre-publish cleanup:

- README files now describe both `1.20.1` and `1.21.1` support lines.
- Capability docs now describe the 1.21.1 data-components path and current verification commands.
- `scripts/package-release.ps1` now packages whichever platforms the branch declares in `enabled_platforms`.
- Tracked `bin/main` outputs were removed from source control.

Remaining release work is branch/tag/release publication, not code cleanup.

## Recommended Order

1. Keep the version matrix pinned and avoid changing dependency versions while fixing source APIs.
2. Add a common abstraction for item identity/data components.
3. Migrate recipe storage to `RecipeHolder<CraftingRecipe>`.
4. Rewrite custom recipe serialization around 1.21 codecs.
5. Update network packets to 1.21 stream/registry-aware encoding.
6. Update JEI transfer/runtime integration.
7. Fix localized Minecraft API changes.
8. Build Fabric and NeoForge modules, then update release scripts and docs.
